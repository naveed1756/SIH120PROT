1Design at a glance

v3 · changes carried back from Layer 3 (25 Sep 2026)
  • Cold production is real. OIL's CSS uplift (39.5%) and share (~23%) show that most oil comes through the cold path. The threshold gradient at reservoir temperature is capped by this evidence (Layer 3A FC-1); cold-zone flow no longer shuts off by construction (C13, T1-C).
  • I1 re-scoped. Rod-drag viscosity checks the wellbore twin's tubing temperature and the rheology level, not the reservoir twin's temperature forecast (Figure 2, C4, I1).
  • Smaller alignments: load and position sampled at ≥ 100 Hz (E1, data items 24–25); N2-annulus pressure named in data item 29; shut-in is a sub-state, not a phase (Figure 3); T2-A has four modes; end-of-natural-flow is F's output; O1 covers hydraulic units; the meaning of OIL's "flowing" is an open question (section 2).

The system is one twin instance per well, built from coupled physical twins (Reservoir T1, Wellbore T2, Surface & electrical T3), kept honest by a state-estimation service that recalibrates them against field data, and read by a layer of diagnostics, forecasting and optimisers that turn the twin's state into decisions. A field-level scheduler sits above the per-well instances because steam generators are shared.

The one chain the whole architecture preserves, from the layer-1 hand-off:

CSS heat input→ temperature field→ rheology (viscosity, yield stress)→ reservoir inflow + rod drag→ rod & pump dynamics→ surface load, torque, energy→ control action Measured load, current, pressure and temperature flow back at every step to recalibrate the chain.
Physics first, ML on the residual

Every prediction has a physics model underneath. ML corrects residuals, classifies patterns and speeds up search; outside its training range it falls back to physics.

Temperature is a field, not a number

T1 carries a coarse radial–vertical temperature grid per well, so steam override, halo collapse and residual heat from the last cycle exist in the model.

Two frictions, kept apart

Viscous fluid drag and mechanical rod–tubing friction are separate terms in the rod model and are calibrated separately.

Three timescales, three loops

Per stroke at the edge, hourly in the cloud, per steam cycle. Each loop sets the envelope for the faster one.

Phase-aware by construction

A well-phase state machine decides which modules run and what "normal" looks like in each phase of the CSS cycle.

Advisory → supervised → closed loop

Hard interlocks stay in the VFD/PLC. The twin earns write access in stages; steam decisions always need human approval.

3Architecture

Six layers, split by where they run. Anything that must react within one stroke runs at the wellsite edge, so a lost link never leaves the pump uncontrolled. Anything that needs history, ensembles or cross-well information runs centrally.

How the twins couple

Each twin owns one part of the physics and publishes a fixed set of quantities to its neighbour. Forward arrows carry the thermal and fluid state from the reservoir up to the motor; return arrows close the loop, because the pump's drawdown sets how much the reservoir delivers and the surface unit's motion drives the rod string.

Coupling solve

Because of the return arrows, the pumped state of a well is a fixed point, found by nodal analysis: the operating point is where the reservoir's inflow curve and the pump's effective delivery agree at the same bottomhole pressure. Three rules make it correct for this field:

  • Pump delivery is computed from the downhole plunger stroke given by the rod model, not the surface stroke (criticals C14, C18).
  • Delivery is reduced by fillage and slippage, both of which depend on intake conditions and viscosity.
  • If no match exists above a minimum intake pressure, the pump is oversized for the current inflow — the physical onset of fluid pound — and the SPM scheduler acts before the card shows it (C17, C19).

Operating phases

A CSS well is not one system through the cycle. The dominant physics, the available sensors and the meaning of "normal" all change by phase, so the twin runs a per-well state machine and tags every record with its phase. Transitions are proposed by the twin and confirmed by an operator event.

InputSource

O — Optimisers

Five optimisers at three timescales. Objectives and constraints come from the layer-1 objective/constraint table (production, steam, SOR, energy, mechanical stress, failure risk; limits on pressure, temperature, SPM, stroke, rod load, motor load, fillage, intake pressure, equipment condition). Each optimiser owns a subset.

O1

Intra-stroke rod-load limiter

Edge · every stroke · closed loop
In
Real-time load and crank angle (beam units) or rod position (hydraulic units); safe downstroke speed from T2-B; SPM target and limits from O2; D1 class.
Out
VFD speed reference for each segment of the stroke.
Method
Sectional (intra-stroke) speed control: upstroke as fast as load and torque limits allow; downstroke slowed to keep the rods in contact with the carrier bar. Feed-forward from the rod model + feedback on minimum downstroke load (rod-load-limiter principle used in industry rod-float mitigation), with slew limits for regenerative energy. On hydraulic long-stroke units the same limiter acts on the hydraulic drive's speed command against rod position instead of the VFD against crank angle.

O2

Cloud · hourly · advisory → supervised

Schedule of SPM, up/down speed ratio, stroke (hydraulic units), idle time, heater power, diluent rate — with expected production, fillage, energy per barrel and risk.

6Innovations

What goes beyond the problem statement. Each innovation names the module it plugs into and whether it is realistic for the SIH prototype or a later stage. The problem statement asks for monitoring, prediction and optimisation of CSS and SRP; these are the places the architecture can add something the brief did not ask for.

Sensing & soft sensors
I1Prototype
The rod string as a downhole viscometer

The drag fitted to every stroke implies an effective viscosity of the oil around the rods, weighted along the tubing. At this field's low rates that viscosity is set mainly by how the fluid cools up the tubing, so it gives a continuous check on the wellbore twin's temperature profile and on the rheology level, without a downhole gauge. It is used only when fluid drag can be separated from mechanical friction, and it is not an independent test of the reservoir twin's temperature forecast.

Plugs into: T2-B → SE → T2-A (profile check), T1-B (level only)
I5Prototype
Virtual dynamometer from motor signals

Reconstruct the surface card from VFD torque and unit geometry, corrected by ML. Keeps diagnostics alive when a load cell fails in the heat, and extends the twin to wells that have no load cell at all.

Plugs into: T3, E2, D4
I12Later · hardware
Low-cost impact and separation sensing

A MEMS accelerometer on the carrier bar and a clamp-separation switch give direct ground truth for rod float and impact — the labels the ML models otherwise lack.

Plugs into: E1, D1, O1 validation
I10Prototype
Deposition early warning

When rod drag rises but the thermal model says the tubing has not cooled, the extra resistance is attributed to asphaltene/wax build-up, prompting hot-oiling before it becomes a stuck pump.

Plugs into: SE, D2, H
Modelling & learning
I8Later
Neural-operator surrogate of the thermal field

A Fourier Neural Operator or DeepONet (or a physics-informed neural network) trained on the thermal model reproduces the full temperature field in milliseconds, enabling large ensembles and real-time what-ifs.

Plugs into: T1-A, T1-D, SE
I6Prototype
Sim-to-real failure library

The rod model generates labelled cards for every failure mode across temperatures, SPMs and geometries; domain adaptation closes the gap to field cards. Solves the "almost no failure examples" problem.

Plugs into: T2-B → D1
I7Later
Few-shot twin onboarding across wells

Hierarchical Bayesian priors share what the field has learned: a new well's twin starts from its neighbours' calibrated parameters instead of from scratch, and each well's data sharpens the field prior.

Plugs into: SE, W1, T1-D
I16Later
Failure knowledge graph

Links each workover to the operating history, cycle stage, settings and diagnostics that preceded it, building a field root-cause memory that also improves the survival models.

Plugs into: P1, D3
Control & optimisation
I2Prototype
Predictive rod-float prevention

Industry rod-float limiters react after the load drops. Here the forecaster predicts when float will start at current settings and O2 steps SPM down ahead of it, while O1 uses the rod model's safe speed as feed-forward — prevention instead of mitigation.

Plugs into: F, O1, O2
I3Prototype
Closed-loop CSS design

Every candidate steam plan is simulated with the pump controller running, so a plan that heats more oil but floats rods early or costs more lift energy is scored for it. This is the literal "integrated" optimisation the brief asks for.

Plugs into: O3 with O2 in the loop
I9Later
Thermal-lift co-optimisation

Downhole heater power and diluent rate become control variables alongside SPM: sometimes a little heat is cheaper than slowing the pump, sometimes the reverse.

Plugs into: O2, T2-A
I15Stretch
Reinforcement learning trained inside the twin

An RL agent learns VFD speed profiles entirely in simulation, then runs only within O1's validated safety envelope — the twin as a safe training ground.

Plugs into: O1, T2-B, T3
Energy, fleet & operator
I4Prototype
Fleet-level steam scheduling

Cut-off decisions and steam-generator bookings are optimised across all CSS wells together, so steam goes where it earns most and wells keep producing while they wait for a generator.

Plugs into: O4, O5
I11Prototype
Whole-site energy and emissions twin

Counts every energy input per barrel — steam-generator fuel, tank heating, heaters, lift electricity — and CO2-equivalent as an objective; can shift pumping to cheaper tariff or on-site solar hours in the Thar.

Plugs into: T3, O2, O3
I13Prototype
Uncertainty-aware, explainable advice

Each recommendation shows its confidence band, the physics reason, the top drivers and a counterfactual ("if unchanged, float in ~14 h"), plus a trust score for the twin behind it.

Plugs into: H, D4, F
I14Stretch
Natural-language operator assistant

A bilingual assistant grounded on the twin's live state answers "why did SPM drop on well 17?" from the audit trail and model outputs, without inventing numbers.

Plugs into: H

7Workflows

Three nested loops run continuously; two more workflows bring a well onto the twin and keep models current.

W1 · Onboard a well

  1. Load master data (trajectory, completion, rods, pump, unit, drive) and sanity-check it against measured static load and stroke.
  2. Fit rheology from lab data, or use the field fluid family and flag it.
  3. History-match past CSS cycles; hold out the latest one.
  4. Validate on the held-out cycle: rates, water cut, wellhead temperature, card shape.
  5. Calibrate rod drag and friction on recent cards.
  6. Run in advisory mode for at least one production period before any write access.

W2 · Every stroke (edge)

  1. Acquire, filter, detect stroke boundaries.
  2. Build the card, run the diagnostic, extract features.
  3. Edge rules check float, impact and load collapse; O1 sets the next stroke's downstroke speed.
  4. On a critical condition the VFD/PLC interlock acts; the twin logs and explains.
  5. Features and events buffered and sent to the platform.

W3 · Hourly (cloud)

  1. Ingest, quality-check, phase-tag.
  2. Update fast parameters; slow ones when due.
  3. Update twin states and run the coupling solve.
  4. Forecast with uncertainty, including float-onset time.
  5. Propose a pumping schedule; show it with reason and effect; send approved targets to O1.

W4 · Per cycle

  1. O4 recommends cut-off daily; operator confirms.
  2. Full history-match of the finished cycle; retrain the cycle proxy and card classifier.
  3. O3 produces a Pareto set of next-cycle designs, verified on the full twin with O2 in the loop.
  4. Engineer selects a design; O5 books a generator slot.
  5. During injection, track delivered heat and re-plan if it deviates.
  6. During soak, assimilate pressure fall-off and recommend soak end.
  7. During flowback, forecast end of natural flow; plan lift installation and initial settings.

W5 · Model lifecycle

  1. Every model versioned with its training window and validity range.
  2. Drift triggers: sustained residuals, falling classifier confidence, a workover changing master data.
  3. Retrained models run in shadow before promotion.
  4. A workover that changes equipment creates a new twin configuration and restarts W1 from calibration.
