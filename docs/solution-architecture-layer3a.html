3How Part A fits together

P1 feeds everything. T1-B is a function library, not a process: T1-A and T1-C call it every time they need viscosity, density or heat capacity. T1-A and T1-C share one radial grid and advance together within each hourly step. T1-D learns from both of them and from P1's cycle history, then answers O3's questions in microseconds.

Order of operations inside one hourly step

T1-A and T1-C are coupled through the grid, and the coupling solve connects T1-C to the pump. They are advanced with sequential operator splitting, lagged by one step. Heat moves slowly compared with one hour, so the lag error is small. The step checks that error and halves the time step if it grows.

  1. Read. Pull this hour's inputs from P1: phase, steam delivered (from T2-A in injection), pwf from the last coupling solve, reconciled rates, and the latest calibrated parameters from SE.
  2. Rates. T1-C computes layer rates qo,k, qw,k (production) or layer injectivities Jinj,k (injection), using last step's T and Sw. In injection, T1-A's allocator (A3) turns Jinj,k and β into the allocation wk (A.4); T1-A owns wk.
  3. Heat. T1-A advances energy and water mass by Δt = 1 h using those rates (backward Euler, fully implicit).
  4. Pressure. T1-C advances the heated-zone pressure ph using the new temperature and the rates.
  5. Curve. T1-C rebuilds the inflow curve from the new temperature field and publishes it to the coupling solve.
  6. Check. If any layer's flow resistance Ik changed by more than 5% within the step, the step is repeated as two half-steps. Then T1-A publishes its summaries and heat budget.

4.1Components

P1.1Ingestion

MQTT broker for Sparkplug B, an OPC UA client for OIL's SCADA, an HTTPS drop for waveform files and batch importers for records. Every write carries a deterministic key, so replaying a message never duplicates a row.

P1.2Validate and harmonise

Converts every value to SI from the unit declared at the source, stamps UTC, and applies the quality checks in 4.4. A value with an unknown unit is rejected and queued, never guessed.

P1.3Stores

Time-series hypertables, a card table backed by object storage, an append-only event and phase log, bitemporal master data, and relational tables for lab results, tests, tank gauging and dispatch.

P1.4Phase tagger

Proposes phase transitions live from signal rules. For old records, it reconstructs phases with a hidden semi-Markov model. An operator confirms every transition.

P1.5Registry

Model versions and validity ranges, calibration sets with covariance, T1-A grid snapshots, and the lineage of which data and configuration produced which output.

P1.6 · P1.7Access and quality

One API that every module uses, including "as of time t" queries. A quality service turns flags into per-sensor health and weekly reports.

4.3Ingestion: two paths by data rate

Sparkplug B works well for reports by exception, and poorly for 30–100 Hz waveforms from 50 wells. The edge therefore splits its output into two paths:

Message path: MQTT Sparkplug B 3.0

  • Topic namespace spBv1.0/BGW/{NBIRTH|NDATA|DBIRTH|DDATA|NDEATH}/{edge_node}/{device}, e.g. spBv1.0/BGW/DDATA/WS-017/SRP. One edge node per well site; devices SRP, VFD, WH, TANK, SG.
  • Birth certificates declare every metric with name, alias, datatype and engineering unit as a metric property. P1.2 converts units from the birth, never from the tag name.
  • Carries SCADA values by exception, per-stroke summaries (SPM, peak and minimum load, fillage, class, float margin), and each card as a DataSet metric (columns position and load, ~200 rows each for surface and downhole).
  • Loss detection: the 0–255 seq counter and bdSeq session number. A gap starts a backfill request.
  • Store and forward: when the primary host's STATE message says offline, the edge buffers. On reconnect it republishes with metrics flagged is_historical, which P1 writes by source timestamp.

File path: raw waveforms

  • The edge writes raw load, position, current, voltage, power and frequency to 15-minute Parquet chunks (zstd), each with a manifest: well, channel list, sample rate, first and last timestamp, SHA-256.
  • Uploaded over HTTPS (outbound only) to the object store. P1 verifies the hash and registers the chunk. A missing chunk is re-requested from the edge buffer.
  • Used for retraining, card reconstruction with new filter settings, and forensic review after failures.
  • OIL systems: read-only through an OPC UA client or the existing historian's API. Their tag names are mapped to ours in the tag table. Which systems exist is an open question (section 11).

A proposal becomes a phase_interval once confirmed in H. If nobody confirms within 12 h, it stays as source=rule with its confidence, and downstream modules may use it for monitoring and forecasts. It is never used to enable write access (O1/O2 supervised or autonomous modes) or as a training label until an operator confirms it. This relaxes Layer 2, which required confirmation for every transition (logged in section 11).

History: hidden semi-Markov model

Old records rarely carry clean phase dates. An explicit-duration HMM (HSMM) reconstructs them:

  • States: the Layer 2 phases baseline, prep, injection, soak, flowback, pumped and workover, plus a shut-in sub-state that can occur inside baseline, flowback or pumped. Cut-off is an event (the end of pumped), not a state. Prep and workover have weak signal signatures, so they are anchored to maintenance and workover records where those exist; otherwise they are decoded with wide duration priors and low confidence.
  • Emissions: daily steam rate, THP, wellhead T, VFD run hours, tank level change, standardised per well.
  • Duration priors from OIL: injection log-normal over 14–21 d; soak 0.5–0.6 × injection. Transitions only in the legal order of the Layer 2 state machine.
  • Decoded with Viterbi, then reviewed by an engineer. Accepted intervals are stored as source=hsmm with the posterior probability as confidence.

4.8Workflows

P1-W1 · Live data

  1. The edge publishes DDATA (SCADA by exception, stroke summaries, cards) and writes waveform chunks every 15 min.
  2. P1.1 decodes, checks seq continuity and writes idempotently by (tag, source ts).
  3. P1.2 converts units using the birth metadata, stamps UTC and applies the quality checks.
  4. P1.4 evaluates phase rules and raises proposals to H.
  5. P1.7 updates per-sensor health. A sensor that turns Bad raises a D4 ticket.
  6. Consumers read through P1.6: E2 features for D1 every minute, and hourly pulls for SE, T1 and F.

P1-W2 · Outage and backfill

  1. The broker loses the edge (MQTT will sends NDEATH), or the edge sees the host go offline.
  2. The edge buffers: first everything, then cards and features only once the buffer passes 80%.
  3. On reconnect it sends a new NBIRTH, then historical data flagged is_historical, oldest first.
  4. P1 writes by source time, marks the gap interval closed, and asks SE to re-assimilate that window.

P1-W3 · Onboarding historical records

  1. Collect well files, CSS logs, production reports, card surveys, failure records and lab reports. Register every file with a hash and a description.
  2. Extract to staging tables. PDFs and scans are transcribed, with a human check on every number that feeds an Essential data item.
  3. Validate units and ranges; resolve conflicts between documents (the newest official source wins, and the loser is kept as a superseded version).
  4. Build asset_config versions from workover dates, so each period has the right rods, pump and completion.
  5. Reconstruct phases with the HSMM; an engineer reviews them.
  6. Derive css_cycle outcomes: oil, length, peak rate and SOR per cycle.

P1-W4 · As-of replay

  1. SE or T1-D asks for well X "as of" time t.
  2. P1 returns data with source time ≤ t and the configuration that was valid at t, as it was recorded then (or with later corrections, if requested).
  3. The model run stores the query in model_run.inputs_hash, so the result can be reproduced.

Security and integration

  • IEC 62443 zones: field devices, edge, DMZ broker, cloud. The edge makes outbound connections only (MQTT over TLS with mutual certificates, HTTPS). No inbound port is opened at a well site.
  • P1 carries no write path to the field. Commands belong to H's dispatch, which has its own signing and audit (Layer 2).
  • Master-data fields map cleanly to OSDU well, wellbore and trajectory records, and trajectories can be imported from WITSML. This keeps a later move onto an enterprise data platform open without depending on one now.

5.2Energy equation in enthalpy form

Writing the balance in terms of volumetric enthalpy H instead of temperature makes condensation automatic. While a cell holds steam, added energy changes steam saturation, not temperature, so the condensation front needs no special tracking.

∂H/∂t + (1/r) ∂/∂r [ r Σj ρj hj uj ] = (1/r) ∂/∂r [ r λ ∂T/∂r ] + ∂/∂z [ λ ∂T/∂z ](A.1) energy
H = (1−φ) ρrcr(T−Tref) + φ [ Soρoco(T−Tref) + Swρwhw(T) + Ssρshs(T) ](A.2) enthalpy
∂(φ ρwSw + φ ρsSs)/∂t + (1/r) ∂/∂r [ r (ρwuw + ρsus) ] = 0(A.3) water mass

uj is the radial Darcy flux of phase j, set by the injection allocation (A3) or by T1-C's layer rates (A4). Vertical convection inside the pay is neglected, because override enters through the allocation. λ is the effective conductivity, taken as the geometric mean λ = λr1−φ λfφ. Cap and base cells have φ = 0. Oil co, ρo and λo come from T1-B; water and steam properties come from IAPWS-IF97.

From enthalpy back to temperature

At each cell, with local pressure p (from T1-C's pressure state):

  • Let Hl(p) be the enthalpy with all water liquid at Tsat(p). If H ≤ Hl, the cell is single-phase liquid and T is solved from (A.2) with Ss = 0 (one Newton step, since it is nearly linear).
  • If H > Hl, then T = Tsat(p) and the excess becomes steam: Ss ≈ (H − Hl) / (φ ρs Lv), capped by the water present in the cell. At OIL's pressures Lv ≈ 1,340–1,410 kJ/kg.

Discretisation

Finite volumes on the r–z grid; backward Euler in time for conduction and upwind advection. Explicit advection is ruled out: the steam velocity at the sandface is ~3 mm/s, which in a 2 cm cell would force time steps of seconds. The resulting sparse system (≤1,900 unknowns, 5-point stencil) is solved with a direct sparse solver (scipy.sparse.linalg.splu). Two to four Picard iterations resolve the H–T relation. Conservation is checked every step (5.4).

5.3Injection, override, soak and production

Injection: how steam is split between layers

ṁk = ṁsf · wk, wk = Jinj,k eβ ζk / Σj Jinj,j eβ ζj(A.4) allocation
qheat,sf = ṁsf [ hw(Tsat) + xsf Lv − hw(TR) ](A.5) heat at sandface

ṁsf, xsf and pbh come from T2-A (injection mode). Jinj,k is layer k's injectivity from T1-C (C.4 with steam and water mobility; it reduces to (kh)k for uniform properties). ζk ∈ [0,1] is the layer's height in the pay (0 at the base, 1 at the top). β is the override parameter: β = 0 means no gravity bias; β ≈ 2–3 puts most of the steam in the top third. It is a calibrated closure, not measured physics (box below). With OIL's 3.1 t/h at x = 0.4–0.7, qheat ≈ 1.5–1.8 MW.

β is a closure parameter, not validated Baghewala physics
  • What it stands for: the net effect of buoyant steam rising through the pay, which a 2-D model without vertical convection cannot compute.
  • Status: Assumed prior, uniform 0–4. No Baghewala value exists.
  • Calibration data: early-flowback water cut and its decline (RWR), produced-fluid temperature through T2-A, soak pressure fall-off, and any temperature log or observation well (question for OIL). I1 (rod-drag viscosity) adds nothing here: at this field's rates the tubing sets the viscosity the rods see (Part B §2), so it does not see reservoir temperature.
  • Procedure: ES-MDA per cycle, jointly with layer kh multipliers and the delivered-heat factor (kVIT in T2-A, or ηsf when T2-A is not run), because they leave similar signatures (section 12). If the posterior stays close to the prior, β is reported as not identified, and outputs sensitive to it carry the prior range.
  • Per well or per cycle: one value per well with a small per-cycle deviation, βw,c = βw + εc, εc ~ N(0, 0.3²). Pay geometry is fixed; rate and pressure change by cycle.
  • Validation: a 3-D thermal simulation (CMG STARS or equivalent) of a reference well computes override directly. The fitted β must reproduce its top-to-bottom heated-radius ratio within 25%, and must stay consistent with van Lookeren (A.13).

Soak

No flow at the well (u = 0). Energy moves by conduction only, while steam condenses as neighbouring cells cool below Tsat. Condensation shrinks steam volume, which T1-C reads as the pressure fall-off, the soak-time signal in Layer 2.

Flowback and pumped production

Flow reverses. T1-C provides qo,k and qw,k per layer. A4 converts them to fluxes u = q/(2πr hk) and carries each cell's enthalpy and water toward the well (upwind). This is how the heated halo collapses in production (C9): the grid tracks the hot oil leaving and cold oil moving in behind it.

When the approximation is acceptable

  • The wellbore is near-vertical across the pay (inclination below ~30° over the pay interval; pay length corrected by 1/cos θ).
  • The heated radius is small against well spacing: rm ≤ 0.3 × half-spacing, checked every step.
  • The pay is thin enough that vertical flow is secondary. Layer 1 reports 5–23 m; the thickest wells are checked first against the reference model.
  • No neighbour interference is flagged, and the grid stays within the spread of the analytical guard-rails (5.6).

Where a higher-fidelity reference is required

Horizontal and fishbone wells; thick pay with strong calibrated override (β > 3); wells with suspected communication; any well where grid and guard-rails diverge persistently. For each such type, one well is run in a 3-D thermal simulator. The comparison either gives corrections (effective radius, heated-volume factor) or marks the well type reduced confidence, which the trust gate treats as a caution (section 13).

Link from yield stress to threshold pressure gradient

G(T) = CG · 2τy(T) / rp, rp = √(8k/φ) ⇒ G = CG τy √(φ/(2k))(B.6) capillary bundle

A Bingham fluid in a capillary of radius rp starts to flow once the gradient exceeds 2τy/rp. With the Kozeny radius √(8k/φ) and CG = 1, the reference rock (500 mD, φ = 0.19) gives G = 0.22, 0.44 and 0.88 MPa/m for τy = 0.5, 1 and 2 Pa. That is the same order as the published 0–0.78 MPa/m, so one yield-stress measurement fixes a physically consistent TPG. At reservoir temperature, field evidence caps it far lower: FC-1 (7.1) requires CG·τy(TR) ≲ 0.03 Pa, i.e. G(TR) ≲ 0.013 MPa/m for the reference rock, at the bottom of the published range. The published values come from other oils; Baghewala's cold production says its yield stress at 50 °C is small or absent. CG (tortuosity) is calibrated in T1-C, within that cap.

6.4Uncertainty, updating and API

  • Fit: Bayesian regression on log μ. The posterior over θ = (A, B, τ0, n0, TNN, a, b, φ100, finv) comes from MCMC (emcee, 32 walkers). Every call returns μ and its σ; SE's ensemble members each draw one θ.

7.1Pressure model: the heated zone as a tank

Layer 2 described the inflow as two zones in series. Layer 3 makes this dynamic: the heated zone is a pressure node that injection pumps up, soak lets down and production drains. The cold zone behind it feeds it and, before the first cycle or once the halo has cooled, carries all the production. How strongly it does so is set by cold-oil mobility and any threshold gradient, and it must match the cold production the field actually shows (FC-1 below).

Vp,h ct,h dph/dt = Qinj,res − Σk qt,k + Σk qc,k − dVs/dt + Vp,h βT dT̄/dt(C.1) heated-zone pressure
qc,k = 2π kkhk λc,k [ pc − ph − Gc(re − rh,k) ]+ / ( ln(re/rh,k) − ½ )(C.2) cold-zone support
Vp,c ct,c dpc/dt = − Σk qc,k + Qbd(C.2b) cold-zone depletion
Baseline (no heated zone, rh,k → rw): qk = 2π kkhk λc,k [ pc − pwf,k − Gc(re − rw) ]+ / ( ln(re/rw) − ½ + sk )(C.2c) cold IPR

Qinj,res: injected volume rate at reservoir conditions (liquid plus vapour, from T2-A). dVs/dt: rate of change of steam volume from T1-A, which is negative during soak and so lowers ph. βT: fluid thermal expansivity. ct,h includes the large effective compressibility of any steam present. λc,k: cold-oil total mobility of layer k at TR, with μapp at the cold-zone shear rate (same fixed-point iteration as 7.2). Gc: threshold gradient at TR from B.6, applied across the whole cold annulus from rh to re. Revision 1's short "connected cold length" ℓ is removed: it was a free closure that made cold support weak by construction. pc: cold-zone average pressure, initialised from the current near-well pressure (P-08) and depleted by C.2b. Vp,c, ct,c: cold-zone pore volume and compressibility (P-16). Qbd: support across the drainage boundary; zero by default, added as a calibrated term only if field pressures show pressure maintenance. [x]+ = max(x, 0). During injection the same expression with reversed sign gives leak-off to the cold zone. Vp,h follows rh from T1-A. C.2c is the same law with no heated zone: the IPR of a well before its first cycle, or long after one.

FC-1 · Field-consistency constraint: cold production is not negligible
  • Evidence. CSS raised output of targeted wells by 39.5%, so their pre-CSS rates were ~70% of post-CSS rates; and CSS wells supplied ~23% of annual field production (OIL, via Business Standard, cited in workflow-research). Some of that cold production may be helped by heaters, diluent or residual heat, but most Baghewala oil clearly comes through the cold path. The figures may be defined differently from how this twin would compute them, so they are used as an order-of-magnitude constraint.
  • What it implies for TPG. With near-well pressure ~75 ksc (P-08) and ~10 ksc at the pump intake, about 6.4 MPa of drawdown is available. Oil at the 150 m drainage boundary can move only if G(TR)·150 m < 6.4 MPa, i.e. CG·τy(TR) ≲ 0.1 Pa for the reference rock (B.6). For cold flow of the observed size without the threshold consuming most of the drawdown (≤ 30%), CG·τy(TR) ≲ 0.03 Pa. Revision 1's placeholder (τ0 = 2 Pa, so τy(50 °C) = 0.57 Pa and G = 0.25 MPa/m) needed ~38 MPa to move oil across 150 m, which shut cold flow off beyond ~25 m.
  • Rule. Every prior draw of (τ0, TNN, a, CG, kh, skin) must reproduce, through C.2c, the measured rate of wells with no CSS in the preceding months (P-42) within its band. Draws that fail are rejected before the ensemble starts (prior-predictive filter), and SE keeps the cold rate as an observation afterwards. Until per-well data exists, the bound above is applied to CG·τy(TR) directly.
  • A second gap it exposes. Even with no threshold at all, the reference well's cold IPR (500 mD, 10 m, 11,500 cP, 6.4 MPa drawdown) gives only ~1.4 bbl/d, and ~6 bbl/d at the top of Layer 1's ranges (1,000 mD, 23 m). OIL's July 2025 figures average ~26 bbl/d per listed well (Part B §2). Real kh is higher than Layer 1's figures, or near-well viscosity is lower (heaters, diluent, shear-thinning, residual heat), or those rates are CSS-dominated. FC-1 makes calibration match measured cold rates instead of inheriting these priors. BGW-SYN-01 (section 9) keeps its values, but its CSS uplift must not be quoted as a Baghewala prediction.

7.2Layer inflow: summed cell by cell

The Boberg–Lantz two-zone formula assumes one hot viscosity and one cold viscosity. T1-A already gives the actual temperature in every cell, so T1-C sums the resistance of the actual profile. The two-zone formula becomes the special case of a step profile and is kept as a check.

qt,k = 2π kkhk [ ph − pwf,k − ΔpG,k ]+ / Ik(C.3) layer rate
Ik = Σi: ri ≤ rh,k ln(ri+½/ri−½) / λt,ik − ½ /λ̄t,k + sk / λt,sf,k(C.4) resistance
λt = kro(Sw,T) / μo,app(T, γ̇) + krw(Sw,T) / μw(T)(C.5) total mobility
ΔpG,k = Σi: ri ≤ rh,k, Tik < TNN G(Tik) Δri (minimum useful drawdown of layer k)(C.6) TPG

The −½ term converts from the pressure at rh to the heated-zone average ph (the pseudo-steady form); λ̄ is the pore-volume-weighted mean mobility. pwf,k is corrected for hydrostatic head between layers. The oil viscosity depends on the local shear rate, which depends on q, so each IPR point is solved by fixed-point iteration: guess q → u = q/(2πrh) → γ̇ (Cannella) → μapp (T1-B) → new q. It converges in 2–5 iterations for shear-thinning oil; tolerance 0.5%.

What the TPG term does in practice. Early in a cycle every cell inside rh is above TNN, so ΔpG ≈ 0. As the halo cools, outer cells of the heated zone drop below TNN and ΔpG grows. Once it reaches the available ph − pwf, that layer's heated contribution stops at any pump speed, and the layer falls back to its cold IPR (C.2c), not to zero. O2 reads Δpmin = mink ΔpG,k to avoid pumping harder against oil that cannot move (C13). Under FC-1 the threshold at reservoir temperature is small, so this term matters mainly in the cooling halo, where the oil is between TR and TNN only if TNN > TR.

Swc(T) = Swc,0 + awc(T − TR), Sorw(T) = Sorw,0 − aor(T − TR) (clipped)(C.8) thermal end points

Water saturation per cell is carried by T1-A's water-mass equation (A.3). T1-C does not need a separate "condensate return" curve: water cut is high early because the near-well cells are full of condensate, and falls as oil from farther out arrives. The returned-water ratio RWR (produced water over injected steam, cold-water equivalent) is tracked as a KPI and is a strong calibration target for β and the Corey exponents. The fitted exponential return curve from Layer 2 is kept only as the fallback when T1-A is unavailable.

8.2Training data: three fidelity levels

  • L1 design of experiments: scrambled Sobol or maximin Latin hypercube over x × s (scipy.stats.qmc), 2,000 runs to start. Each run is a full cycle of the coupled twin at its current build stage (Part B 5.10). At stage v0 a reduced pump model stands in for T2-B, T3 and O2, so float day is not predicted and lift energy is approximate; from v2, O2 operates the pump and both become real outcomes (Layer 2 I3). L1 is regenerated when the stage advances. About 1 CPU-minute per run at v0, so a few CPU-hours per batch. At v1–v2 this holds only if the rod model runs at reduced cadence: a ~150-day cycle is ~1.3 million strokes, and simulating each would be one to two orders of magnitude slower. Inside full-cycle runs, T2-B and O2 are therefore evaluated quasi-steadily, one representative stroke per hour per member, with per-stroke simulation kept for O1 studies and float-onset checks.
  • States are sampled, not only designs: for each run the initial state is drawn from end-of-cycle states in the SE ensemble (cycles 1–10), so the proxy learns how residual heat and depletion change the answer.
  • Active learning: after each O3 run, 100–200 extra L1 runs are placed where the proxy's normalised q10–q90 spread is widest among near-Pareto designs. This needs no GP; if the optional GP twin is added later, its predictive variance can replace the spread.
  • Real cycles: OIL reports 39 cycles by 22 Jun 2025, with more since. Each needs phase dates, steam totals and daily production; its state features come from the SE history match (as-of queries).

  • Discrepancy δ: ridge or depth-2 GBT on L2 residuals, with f1's median as an input and a per-well random offset uw. This is where hierarchical priors (I7) plug in later. With ~50 real cycles, δ must stay simple or it will overfit.

  • GP twin (optional): Matérn-5/2 ARD in GPyTorch or BoTorch on L1 + L2 (D.2). Needed only if O3's optional Bayesian refinement is enabled (Part B, revised 5.5). Not part of the SIH prototype.
  • Validity: every query is checked against the training envelope (Mahalanobis distance in standardised inputs plus an isolation forest). Outside it the answer is flagged, and O3 must verify that design on the full coupled twin.
  • Explanations: SHAP TreeExplainer per design for H ("Eres is the top driver of the oil gain"); Sobol indices (SALib) on the GP for field-level sensitivity reports.

After every cycle (W4 in Layer 2)

  1. O4's cut-off is confirmed; P1 closes the cycle record and derives its outcomes.
  2. SE history-matches the finished cycle; the end state is written as the start state of the next.
  3. The new real cycle is added to L2; δ is refit and the CQR quantile Q̂ recomputed.
  4. If the cycle fell outside its predicted 80% band, 200 L1 runs are added around that well's state and f1 is retrained.
  5. The new version runs in shadow on the next O3 design; it is promoted only if its design ranking agrees with the full twin (below).

Acceptance (proposed; agree with OIL)

  • Leave-one-well-out median cycle-oil error ≤ 25%; next-cycle forecast (train on earlier cycles, test on the next) ≤ 20%; SOR the same. Reported separately.
  • 80% band coverage between 70% and 90% on held-out real cycles.
  • Ranking fidelity: Spearman ρ ≥ 0.9 between proxy and full twin on 200 held-out L1 designs per well state. For an optimiser, ranking designs correctly matters more than absolute accuracy.
  • Pinball loss and CRPS reported per output, with the baseline "repeat last cycle's design" for comparison.

Validation that tests generalisation

  • Leave-one-well-out (primary): every cycle of a well is held out together. Tests whether the proxy works on a well it has never seen.
  • Next-cycle forecast (secondary): for each well, train on its earlier cycles and predict the next. This is how the proxy is actually used.

  • Input: Mahalanobis distance in standardised design × state space, plus an isolation forest trained on L1 ∪ L2 inputs.

Hard rule for SE

I1 checks the tubing (T2-A's temperature profile) and T1-B's rheology level; it is not a check on T1's reservoir temperature (Layer 2 v3). Designed identification test (proposed). An SPM step test: hold three speeds (−20%, nominal, +20%) for at least 20 strokes each while temperature is steady. Viscous drag changes with speed and Coulomb friction does not, so the test separates the two. It is run at onboarding and after each workover, and SE can request it when ambiguity persists. 12.3How the study is run

  1. Structural identifiability. On BGW-SYN-01, compute the sensitivity matrix J = ∂y/∂θ of every observable signal, sampled at the rates OIL actually records, with respect to every parameter. Form the Fisher information F = JᵀΣ⁻¹J. Small eigenvalues mark directions the data cannot see; correlations from F⁻¹ show which parameters trade off.
  2. Practical identifiability. Profile likelihood for each parameter on synthetic data with realistic noise, gaps and daily tank gauging. A flat profile means the parameter cannot be identified from that data, whatever the equations say.
  3. Data worth. Repeat steps 1–2 with each candidate addition (SPM step test, annulus pressure log, temperature log, downhole gauge, extra water-cut samples). Rank them by how much posterior uncertainty they remove. This is the evidence behind sensor and data requests to OIL (Layer 2 items 28 and 31).
  4. Re-parameterise. Estimate only identifiable combinations (e.g. the delivered-heat factor); fix the rest at priors. Record the result in the registry as identifiable | joint | not identifiable with current data.
  5. Repeat on real data after the data audit, because real sampling and noise usually make things worse than the synthetic case.

13Uncertainty end to end

Uncertainty is never collapsed into a single deterministic value before a decision is made. One shared ensemble carries it through every module.

Rules

  1. One shared ensemble. Member m carries a joint draw: rheology θBm from T1-B's posterior, reservoir and wellbore parameters θm from SE, and its own states (temperature grid, ph, formation memory). Every module evaluates member m with member m's inputs.
  2. No averaging in the middle. No module passes a mean to the next one. P10/P50/P90 are computed only where they are used.
  3. Proxy plus state uncertainty. T1-D's quantiles describe proxy uncertainty for a given state. State uncertainty is added by evaluating T1-D on all 64 member states and pooling the results into one predictive distribution.
  4. Decisions use distributions. O3 ranks designs on pooled P50 and a tail CVaR, and checks limits on pooled P90. With a 16-member verification subset the tail is the worst 2 members (≈12.5%); Part B 5.4 gives the member selection and pass rules.
  5. Model-form error is counted too. What parameters cannot express (5.8 and 7.7) is carried by T1-D's conformal inflation on real cycles and sized by the reference-model comparisons.

Upstream physics dominates downstream decisions

The dependency runs rheology → thermal and inflow → wellbore → pump → production → optimiser. A T1-B error enters every downstream model in the same direction, so the ensemble can look tight while being biased if T1-B's prior is wrong. Three protections:

  • T1-B's prior band stays deliberately wide until lab data exists (section 14 ranges).
  • A global sensitivity analysis (Sobol indices, SALib) on BGW-SYN-01 ranks which upstream parameters drive O3's choice of design. It is repeated whenever the registry changes.
  • Every O3 recommendation lists its top-3 upstream sensitivities, e.g. "ranking depends on the Walther slope B, which is still a placeholder".
